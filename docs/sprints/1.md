## 2. Транспорт и кадрирование

| ID | Требование | Где реализовано |
|---|---|---|
| TR-1 | TCP-сервер и клиент | `internal/node/node.go`: `Start`, `acceptLoop`, `handleConn`; `internal/transport/conn.go`: `Dial`, `WriteFrame`, `ReadFrameWithDeadline` |
| TR-2 | Собственное кадрирование поверх TCP | `internal/protocol/frame.go`: `Frame`, `Marshal`, `ReadFrame`, `FrameDecoder` |
| TR-3 | Заголовок 24 байта: `version`, `type`, `flags`, `request_id`, `payload_length` | `internal/protocol/frame.go`: константа `HeaderSize = 24`, поля `Frame` |
| TR-4 | Порядок байтов big-endian для многобайтных полей | `internal/protocol/frame.go`: `binary.BigEndian.PutUint16` / `PutUint32` |
| TR-5 | `MAX_FRAME_PAYLOAD = 65536`, проверка до выделения буфера | `internal/protocol/frame.go`: `MaxFramePayload`, проверка `int(length) > maxPayload` до `make` |
| TR-6 | Обработка частичного заголовка и payload | `internal/protocol/frame.go`: `io.ReadFull` для заголовка и payload |
| TR-7 | Обработка нескольких кадров в одном чтении | `FrameDecoder` в `frame.go`, тест `TestStream100Frames` |
| TR-8 | Отклонение неизвестной версии, типа, завышенной длины | `internal/protocol/frame.go`: `ErrBadVersion`, `ErrPayloadLarge`; `internal/node/node.go`: `dispatch` |
| TR-9 | Тайм-ауты соединения и чтения | `internal/transport/conn.go`: `Dial` с `ConnectTimeout`; `ReadFrameWithDeadline` с `ReadTimeout` |
| TR-10 | Корреляция запроса и ответа по `request_id` | `internal/protocol/codec.go`: `NewRequestID`; `internal/transport/client.go`: `RPCClient.Call` |

## Итог спринта 1

Все обязательные, желательные и опциональные требования этапа 1
выполнены:

- E1-1 … E1-6 (обязательные) — реализованы и протестированы;
- E1-7 (желательное) — расширенная обработка ошибок с тестами
  `TestServerSurvives*`;
- E1-8 (опциональное) — сравнение JSON/MessagePack/CBOR с числами в
  `docs/Serialization comparison.md`.

Контрольный результат этапа 1 достигнут: два независимых узла
обмениваются кадрами переменной длины, корректно обрабатывают
частичные чтения, склеенные кадры, завышенную длину и неизвестные
типы, не завершая процесс при ошибочном вводе от удалённой стороны.
